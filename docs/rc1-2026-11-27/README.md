## 首次种子与正式链路的必要修复

种子位于 `config/business-seed.json`，是正式最小输入，不从实验报告、会话缓存或网络搜索provider自动读取。状态文件不存在时，生产刷新、候选装配和人工导入入口才引入种子；存在时不重新套用种子、不刷新旧来源时间、不覆盖人工决定。已存在但损坏的状态不会被空种子悄悄重置。

手动Pages入口现在在上传前装配业务状态并拒绝空数据。仍校验实际已有v1/v2合同与24小时快照时效，不把所有城市/所有新分类的完整覆盖作为基础试用前置条件；现有老新闻快照的exam分类尚未采集会真实报告。定时刷新内部的全范围候选质量门槛保持原状，未通过时只保留旧有效数据和失败健康信息。

旧手动采集入口原先直接采集、且只提交v1，会遗漏v2/business并存在失败路径提交不完整候选的风险。现改为复用 `refresh_service` 暂存校验链路，验证保留数据合同后一起提交 `site/api`，采集失败仍明确报告失败。未改变main及完整SHA授权门禁，没有触发任何工作流。定时计划定义仍为北京时间08:00/16:00，不能承诺平台准点执行，按实际采集时间判断时效。

人工Agent导入仍使用 `python -m scripts.business_service --snapshot-dir <隔离副本/api/v1> --input <最小输入.json>`。完成来源复核后显式提交待发布业务状态及输出，不仅上传一个未持久化的临时页面；本轮只准备隔离数据，没有执行该生产数据提交。免费provider不是任何生产刷新/发布入口的依赖，本轮没有调用独立免费provider、模型API或购买服务。长期稳定性单独开展，不列入本版阻塞。

## 可执行回滚

原生产产物备份在本地 `review/rc1-production-backup/site`，压缩备份 `review/rc1-production-backup.zip`；[完整文件及压缩包哈希](production-backup-manifest.json) 对应生产2091133。已实际准备 `review/rc1-rollback-final`，恢复旧静态页面并逐字节保留当前14个API文件，包含新观察和任何人工核验记录。执行命令：

```sh
python -m scripts.prepare_rollback --backup-site review/rc1-production-backup/site --backup-manifest docs/rc1-2026-11-27/production-backup-manifest.json --current-site review/rc1-site --output review/new-rollback
```

上述路径用于本轮演练。未来回滚时，`--current-site` 必须是当时读取并核对生产版本的新副本，不能直接重复使用已过时的RC1目录，否则无法保留后来新增的人工决定。

工具只允许新的本地review目录，核验备份哈希、拒绝覆盖已有目录，不部署、不改Git、不调用采集器。此为“旧页面+当前最后有效API”的可逆回滚；不会拿旧API覆盖新人工决定。若需回退损坏的数据版本，先暂停刷新并人工比对后续核验决定，再从最后有效快照协调恢复；本工具不会冒险自动执行数据降级。未来真正上线/回滚均需要最终授权及相同产物校验，CatDesk和经营数据库不参与。
