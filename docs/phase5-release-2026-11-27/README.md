# Phase 5 发布候选验收

建议：**GO 继续隔离、人工辅助试用；NO-GO 直接合并并对外部署为无人值守业务服务。** 本轮没有合并、部署、触发生产任务、写经营数据库或自动升级 verified。基于 Phase4 `29f99b024929caac9edffe03235f1ee1843f2c15`，沿用 Draft PR #10。

业务试用已有可审阅的三城页面、25 条累计候选的持久化链路和轻量接口。它们来自已保留的真实来源证据及本轮限定复查，不能算作本轮新发现的25项活动。独立人工业务验收仍未完成，发现率、日期/城市准确率和真实住宿增量均未验收。

## 搜索 provider 的实际结论

匿名 Bing RSS 三城检索受 robots/主机限制，不绕过。Tavily keyless 经独立 Python HTTP 请求实测，第一组3次、按演唱会/考试拆分的第二组6次均返回200，每次最多5条结果；没有账号、密钥或付费调用。见 [原始小规模探测](keyless-provider-probe.json) 与 [分任务探测](provider-task-probe.json)。这些是自动程序实际返回的线索，不是会话内搜索代替程序。

拆分任务后能找到陕西考试入口、济南人事考试栏目、天津招考及演唱会报道；混合查询中仍出现2010/2024旧活动、异地财经新闻，部分标题乱码。返回成功不代表活动有效、最近7天官宣或城市/日期正确。尚未接受其无人值守质量与稳定性；无搜索结果自动进入事件链路。本轮没有完成全平台覆盖或长期限额测试。

## 正式候选链路

`refresh_service` 在已有暂存/质量检查之后构建 `api/business`，与经检验的快照一起进入候选发布；失败时旧事件、历史及人工决定继续保留。生产入口的静态依赖没有到达 `phase*` 实验模块。

新侧车只自动适配具有明确日期证据的官方候选；普通新闻仍由 v1/v2 原合同提供。无法适配的行显示 `official_rows_not_adapted`，不会编造字段。官方结构化日期记录扩展到365天。自然语言公告的自主发现/提取仍不是当前生产采集器的完整能力，不把实验程序接到生产来掩盖这一缺口。

稳定身份使用原 record ID 与 v2 membership/aliases，不靠相似名称自动合并。新证据按观察时间追加；重放同一条输入幂等；乱序不覆盖最新状态。官宣、开票、售罄、加场、延期、取消有独立观察类型。无日期状态更新保留原活动日期，日期冲突移出日历进入情报。全国考试保留全国范围，不推导本地考点。未再次发现不取消；不支持据消失推断售罄或取消。

人工 verified/rejected 决定从已有状态及 v2 保留。新的自动证据只形成待核验观察；v2 人工决定优先。服务不向 v1/v2 写入导入候选，不改变原接口、事件身份和消费者合同。

## 人工辅助操作与发布装配

生产快照未被本轮改写。当前源树直接静态预览可能尚无 `api/business` 数据；页面会显示不可用提示，并可展开原日历。可供业务验收的完整候选装配位于本地 `review/phase5-rc`；复查后的隔离页面位于 `review/phase5/site`。两者都没有部署。

标准输入为 [agent-import-1 示例](agent-import-example.json)。只允许稳定ID、事件/城市/范围/活动日期、带时区观察时间、来源、最多3段各160字原文证据等白名单字段，禁止导入核验状态、联系方式和正文。证据短引只是候选依据，不代表已人工确认真实性。相同活动的状态更新沿用稳定ID，重新观察使用独立时间。

```sh
# 独立免费搜索，返回线索，不自动入事件库
python -m scripts.search_provider --query "天津 演唱会 加场 官宣 2026年11月" --output review/search.json
# 装配一个新的、空的本地候选目录，不部署
python -m scripts.build_release_candidate --output review/new-rc --agent-import docs/phase5-release-2026-11-27/agent-import-example.json
# 完成逐条正文核查后，向隔离副本增量导入
python -m scripts.business_service --snapshot-dir review/new-rc/api/v1 --input review/approved-agent-import.json
```

导入工具拒绝直接写 `site/`；装配工具只允许新的 `review/` 子目录。启动本地静态服务器查看候选即可。页面默认只请求 focus，切换业务视图按需下载对应端点，展开历史时才下载旧新闻。没有新增遥测或外部前端服务。

## 调度与运行预算

保留既有北京时间08:00/16:00的 main 采集计划定义；本轮没有执行，也没有添加生产搜索任务。建议获准上线后，官方采集沿用此计划；人工检索/导入每日一次，重大加场/取消即时复核。连续失败继续保留数据并显示失败，来源超过48小时未复查给出提示，不能用页面重新生成时间刷新来源时效。

自动搜索仍应单独试运行至少7天，固定任务/查询预算，遇429停止而不切付费；先核验日期、城市和一手证据，再显式导入。正式上线前需明确值班人和失败通知去向，本轮没有擅自发送消息或创建通知服务。当前 state 保留历史不自动裁剪，changes仅返回最近200条，需监测状态文件增长及做版本备份。

## NO-GO 项与解除条件

1. 独立人工业务样本尚未签收；本轮截图可见性检查不是日期/城市真实性验收。优先复核未来90天三城重点候选、日期冲突及重复展会，接受指标前不声称发现率达标。
2. 搜索 keyless 短时可用，但免费上限、长期稳定性及国内任务质量未达服务承诺；基础人工辅助试用可继续，不能宣传为无人值守搜索Agent。
3. 当前分支已精简公开原始正文及归档，扫描未发现非测试联系方式/凭据模式；**既往已推送提交仍含历史归档对象**。本轮没有重写远端历史。发布前应由仓库维护者判断历史隐私/版权处置范围；不能把删当前文件描述为历史完全清除。
4. 首次业务状态种子需要从已审阅的标准输入装配并显式发布。不能只合并页面代码后声称业务数据已经上线。运行两轮的是限定来源复查，不是整个生产任务及部署演练。

## 回滚方案

发布候选未改变线上版本，现在无需回滚。未来若获准发布，发布前保存代码SHA、最后有效静态快照及 `api/business/state.json` 的版本/哈希；若失败，停止后续发布并恢复上一份**已验证**静态产物，保留新观察作为隔离待审资料。回滚页面和业务feed时保留其间人工核验记录，不用旧备份覆盖新人工决定。v1/v2维持既有合同，CatDesk及经营数据库不参与。任何回滚部署及合并仍由用户另行决定。
